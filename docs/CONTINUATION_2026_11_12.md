## Implemented

- Income-plan reads return a persisted revision. Saves require `expectedRevision` and `opId`, lock the household, recheck permissions, and compare before replacing any line. Conflicts and transaction failures leave every line unchanged. Identical retries return the saved result. Web and Android preserve their draft and require an explicit discard/load after conflict.
- SimpleFIN claims setup tokens, encrypts access credentials, previews posted history, maps visible ledger accounts, and explicitly imports selected rows through the existing ledger rules. Duplicate provider ids are skipped across retries and reconnection; changed rows require review. Web pagination keeps selected types/counter-accounts/refund links. Android provides the USD connection/preview/single-row import flow. AmFirst coverage is unverified.
- Finnhub supplies dated USD stock/ETF quote previews with explicit confirmation. Permissions, expiry, existing-price changes and currency are checked. The latest saved quote has deterministic ordering even when timestamps match. Preview is read-only; confirming can change investment valuation, not cash.
- Lot creation uses operation ids. Basis edits and sales check lot revisions in the locked transaction. FIFO uses integer quantities and BigInt allocation; partial sales conserve remaining basis and proceeds remainders. A sale reduces the holding and retains realized-gain history without posting a second cash record. Both interfaces offer creation, basis edits, preview, confirmation and history. Personal-space and private-account holdings are hidden from other members.
- The monthly retirement model accounts separately for traditional and other funds, spending, gross withdrawals, assumed tax, unmet spending/distributions, annual cent remainders and previous-December balances. Unused required distributions stay in other funds. Web/Android compare withdrawal orders. Unsupported inherited/younger-spouse distribution tables are refused explicitly.
- SMTP sends newly queued account mail only when enabled and configured. Old local outbox rows are never released as a backlog. FCM HTTP v1 uses server OAuth and generic data-only messages; Android has consent enrollment, sign-out/opt-out cleanup and posting receipts. Remote alert copies honor household channel preferences, enrollment, quiet hours, snooze, membership and target visibility. Provider acceptance is not proof of delivery. Test sinks remain separate.
- Receipt OCR compares quarter-turn readings when text is weak. The original short-text orientation detector had read a rotated Windows fixture upside down. The Windows test fixture also supports explicit Python/font paths. Sharp is pinned for image rotation; Tesseract and Poppler still do the recognition/extraction locally.
- Updated Zod to 4.6.7 and the Hono Node adapter to 2.1.8 after the production dependency audit reported input-validation and static-file advisories. Record schemas were migrated for Zod 4. The final production dependency audit reported zero known advisories; that is not a complete security audit.

Setup, prices, API limitations and service configuration are in [PROVIDERS.md](PROVIDERS.md). The API contracts for income-plan saves, lot creation, basis edits and sales changed; old clients lacking their revision/operation fields must update with the server.
